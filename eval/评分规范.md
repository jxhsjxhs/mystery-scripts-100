# 百局 · 100 本剧本杀「8 位学生评审 + PM 总榜」评分规范

> 本文件是**唯一契约**。8 位学生评审 agent 与 1 位 PM agent 都必须先读它。
> 全程**中文**：评语、荐语、总结、报告一律中文；只保留编号（H01/T01/C01/O01）、数字分数、表格符号。

---

## 一、要做什么

对已有的 **100 本盒装本**（恐怖本 H01–H25 / 反转本 T01–T25 / 搞笑本 C01–C25 / 职场厮杀本 O01–O25）**逐本打分评价**：

1. **8 位学生评审**，每人有**互不相同的学生人设与审美标准**（见第三节），各自独立给 **100 本全部打分**，不得漏本、不得只评自己喜欢的卷。
2. **1 位 PM agent** 汇总 8 人分数，按**综合均分从高到低**排出 100 本总榜，写出评审总结与十佳荐语。
3. 总榜与 PM 总结会**写进每一本的介绍**（`盒装本/<编号>_<剧名>/盒面文案.md` 等）与**项目介绍**（`README.md`、`评审总榜.md`）。

---

## 二、评价依据（零剧透）

学生**只能**读 `eval/mat_<卷>.md` 四份素材表（每份 25 本，约 6KB）。素材表只含公开信息：

- 编号 / 剧名 / 题材 / 人数 / 时长 / 难度
- 一句话卖点
- 公开背景（开场就给全体玩家的疑云）
- 角色名 + 公开身份 / 表面主张

**严禁打开** `horror/*.md`、`twist/*.md`、`comedy/*.md`、`office/*.md` 终稿全文，也严禁读 `盒装本/*/主持人手册.md`、`结局卡.md`、`角色剧本/*`（这些都含真相）。理由：评语要印在盒面上给**没玩过的人**看，读了真相极易写漏。

> 判定标准：**没玩过的人读完评语只想买、猜不出答案**。

## 四、评分格式（严格）

每位学生产出 **4 个文件**（分段落盘，见第五节）：

`eval/scores/sNN_H.md`、`eval/scores/sNN_T.md`、`eval/scores/sNN_C.md`、`eval/scores/sNN_O.md`

每个文件恰好 **25 行**，对应 H01–H25 / T01–T25 / C01–C25 / O01–O25，行格式（竖线分隔，**评语里不得出现竖线**）：

```
编号|分数|一句评语
```

示例（s01 的 `s01_H.md` 前两行）：

```
H01|91|雨夜红白灯笼压得稳，民俗气从盒背就渗出来。
H02|84|赶尸点数这个母题新鲜，段落再收一收会更利落。
```

硬约束：

- **分数**：整数，**60–98**。请**拉开差距**（同一份文件里最好覆盖高、中、低档），不要 25 本都给同一档，也不要全给满分。
- **评语**：**一句话、≤ 24 字、全中文、零剧透**。写「看完公开介绍后的直观感受 + 一句为什么」，可夸可挑刺，但不得点破任何谜底。
- **零剧透禁用词**（评语里出现视为不合格）：真相、真凶、凶手、凶手是、结局是、谜底、解法、幕后黑手、其实是、原来是、竟是、居然是、隐藏秘密、个人目标、身份对调、数字分身、替身演员、失忆是假、调包者。
- **不得出现**拉丁字母/英文/拼音（编号 H01 等除外）、不得出现剧透、不得复述谜底。
- 每份文件**只写 25 行数据**，不要写标题、不要写表头、不要写总结、不要写 markdown 表格。

---

## 五、分段落盘纪律（必须遵守）

历史教训：一次性读入大表 + 一次性输出 100 行，agent 多次 `failed before it finished` 零输出。因此：

1. **不要一次性读四份素材表**。
2. 按 H → T → C → O 顺序，**每次只 `read` 一份 `mat_<卷>.md`（25 本，很短）**。
3. 读完**立刻 `write` 落盘**对应的 `sNN_<卷>.md`（25 行），**先落盘再读下一份**。
4. 四份全部落盘后，用 `send_message` 报告：4 个路径、每个 25 行、分数区间、自查结论。
5. **只改自己代号开头的 4 个文件**，绝不碰别人的、绝不碰素材表/终稿/scripts/README。
6. 不建 todo、不派子 agent、不跑脚本、不做 git。

## 六、PM agent 的任务（学生全部完成后才启动）

PM 读 `eval/pm_input.md`（含 8 人全部分数、均分、机器排名、分卷统计、TOP/BOTTOM 名单），产出 **`eval/PM评审总结.md`**，固定五节：

```
# 百局 · 100 本剧本杀评审总榜（PM 汇总）

## 〇、评审团总荐语
> 一句话，≤ 40 字，全中文、零剧透。这一句会被写进 100 本每一本的介绍里。

## 一、评审方法与总览
（200–350 字：8 位学生人设各异、各自独立打分、按 8 人均分排序；总体分数分布、最高/最低分、四卷整体气质差异）

## 二、十佳逐本荐语
| 名次 | 编号 | 剧名 | PM 荐语 |
| 1 | XXX | 《XXX》 | ≤ 30 字，零剧透 |
…（恰好 10 行，名次 1–10，编号/剧名必须与 `pm_input.md` 的 TOP10 逐字一致）

## 三、分卷观察
（四卷各 80–120 字：本卷均分、上榜特点、适合谁）

## 四、给店家与玩家的选本建议
（3–5 条，按人数 / 难度 / 场景给建议，零剧透）

## 五、全体名次表（100 行）
| 名次 | 编号 | 剧名 | 卷 | 均分 |
| 1 | XXX | 《XXX》 | 恐怖本 | XX.X |
…（恰好 100 行，名次 1–100，**顺序必须与 `pm_input.md` 的机器排名完全一致**，编号/剧名/均分逐字照抄）
```

PM 红线：**全中文、零剧透**（同第四节禁用词）、不改动任何分数与名次、不写 100 本逐本点评（只写十佳）、不碰其它文件、不建 todo/不派子 agent/不做 git、分 2–3 段落盘（先 `write` 〇+一+二，再 `edit` 追加三+四，再 `edit` 追加五）、完成 `send_message` 报告。

## 七、 captain 后续（不用 agent 做）

- `scripts/aggregate_scores.py`：校验 8×4 份评分 → 算 8 人均分 → 降序排名 → `eval/评分汇总.json` + `eval/总榜.md` + `eval/pm_input.md`。
- `scripts/finalize_review.py`：把「名次 / 均分 / 分卷名次 / 评审短评 / PM 总荐语 / 十佳荐语」注入 100 本 `盒面文案.md`、`主持人手册.md`、`本盒完整内容.md`（幂等，可重复跑）；生成 `评审总榜.md`；更新 `README.md` 与 `盒装本/盒装本总索引.md`。
- `scripts/verify_review.py`：校验 100 本介绍都带评审名片、编号/名次与 JSON 一致、零剧透、全中文。
- 最后 `validate_pack.py` / `verify_box.py` 复核、更新 README、提交推送 GitHub。
