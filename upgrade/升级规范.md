# 百局 · 低分本「讨论精彩程度」升级规范（唯一契约）

> 本文件是 6 位写手 agent 与 6 位导师 agent 共同遵守的唯一契约。全中文。
> 目标：把评分低于 85 的 89 本，在**不改动原设定、不剧透**的前提下，把「玩家围坐讨论时的精彩程度」升级——让每一幕都有可吵的争点、有两难抉择、有主持人可抛的高光爆点、有角色之间天然对撞的钩子。

## 一、分工与分组

- 6 个写手 agent，编号 w1–w6，各领一组（15/15/15/15/15/14 本，共 89 本）。
- 6 个导师 agent，编号 w1–w6，与写手**一一对应**，只回归自己那一组。
- 组号 → 编号清单以 `upgrade/分组.json` 为准；每本公开素材在 `upgrade/materials/<组号>.md`。
- 评分不低于 85 的 11 本（C25/T01/C03/O04/T18/O17/C10/C15/H01/T08/C01）**不参与升级**，保持原样。

## 二、写手能读什么、绝不能读什么

- 只读：`upgrade/升级规范.md`（本文件）、`upgrade/materials/<自己组号>.md`。
- **严禁**打开四卷终稿全文、`盒装本/*/主持人手册.md`、`结局卡.md`、`角色剧本/*`、`review/`、`commercial/pack_*.md`。
- 理由：素材表已刻意剔除反转 / 真相 / 结局 / 隐藏秘密 / 个人目标；写手凭空知道答案，就写不出「没玩过的人也能吵起来」的争点，且极易漏剧透。

## 三、升级内容必须遵守的红线（导师据此回归）

1. **零新增**：不得凭空新增人物、道具、地点、时间、设定、机制。所有争点、抉择、钩子必须能从素材表里的「公开背景 / 核心机制 / 关键线索 / 三幕流程 / 公开角色」自然长出来。
2. **零剧透**：不得出现反转答案、真相、真凶、结局、隐藏秘密、个人目标、核心诡计解法；不得写「其实 / 原来 / 竟是 / 真相是 / 凶手是 / 幕后 / 身份对调 / 替身演员 / 数字分身 / 调包者 / 失忆是假」等泄露句。争点只能停在「谁说得通、该信哪条物证、这一票怎么投」。
3. **角色名逐字一致**：`**对抗钩子**` 里出现的角色名，必须与素材表 `角色（名字 → 公开身份 ｜ 表面立场）` 段的名字逐字一致，不得自造简称或改名。
4. **三幕对齐**：`**分幕争点**` 必须恰好三行，分别对应素材表「三幕流程（原文）」的第一 / 二 / 三幕，不得改幕次、不得加第四幕。
5. **全中文**：除编号 `[H02]`、`↔`、数字外，不得出现拉丁字母 / 英文 / 拼音。
6. **不改结构**：不改编号、剧名、人数、角色名、线索条数、题材、时长、难度；升级内容是**追加**的一个独立段，不重写原有 9 字段。

## 四、写手产物格式

- 路径：`upgrade/drafts/<组号>.md`（例如 `upgrade/drafts/w1.md`）。只改这一个文件。
- 文件开头可写一行 `# 第 N 组 · 讨论升级稿`；随后**恰好 15 块（w6 为 14 块）**，按组号清单顺序，编号连续、不重不漏。
- 每块格式**逐字**如下（`**标签**` 六个，顺序固定；块与块之间空一行）：

```
## [H02] 《赶尸·点数》
**讨论焦点**：<40–70 字，一句话点明这局最该吵起来的核心争议>
**分幕争点**
- 第一幕：<25–45 字，此时玩家该争什么、谁与谁对上>
- 第二幕：<25–45 字>
- 第三幕：<25–45 字>
**两难抉择**
- <20–40 字，一个真的两难、怎么选都有代价>
- <20–40 字>
**高光引导（主持人宣读）**
<50–90 字，主持人可当场念出、把讨论推到最热的提问或情境；只制造张力，不给答案>
**对抗钩子**
- 赶尸·麻叔 ↔ 赶尸·老陀：<20–40 字，两人公开立场天然对撞处>
- <再来一行，≥2 行；角色名必须出自本本公开角色名>
```

- 字数区间为**软约束**（写顺为先）；硬约束是六个标签齐全、`**分幕争点**` 恰好 3 行、`**两难抉择**` ≥2 行、`**对抗钩子**` ≥2 行、角色名合规、零剧透、全中文。
- **分段落盘纪律（务必遵守）**：本组 15 本分 **5 段 × 3 本**落盘——先 `write` 第 1 段（文件头 + 前 3 块），再用 `edit` 逐段追加（4–6 块 / 7–9 块 / 10–12 块 / 13–15 块）。**绝不一次性输出整组**，否则会像历史多次那样 `failed before it finished` 零输出。w6 为 14 本，最后一段 2 本。
- **逐段读素材（务必遵守）**：素材表约 30–50KB，**严禁一次性整表读入**。先用 `grep -n '^## \[' upgrade/materials/<组号>.md` 拿到每本起始行号，再用 `read offset=<起始行> limit=<到下一本前>` **每次只读 3 本**，立刻写出这 3 块，再读下 3 本。每本的行号区间会由 captain 在任务消息里直接给出，照抄即可。

## 五、导师产物格式（合理性回归）

- 导师读三样：`upgrade/升级规范.md`、`upgrade/materials/<组号>.md`（公开素材）、`upgrade/drafts/<组号>.md`（写手稿）；**可**用 `grep -n '^## \[' <对应卷终稿>` 定位后 `read offset/limit` 分段核对本组各套的角色名 / 线索 / 三幕是否被写改串（禁止整卷一次性读入）。
- 导师产**两个**文件，其余一律不碰：
  1. `upgrade/approved/<组号>.md`——**回归定稿**：与写手稿同格式、同样块数、同样编号顺序；逐本把「新增了设定、剧透、角色名错、争点接不上线索、三幕对不上、语句不通」的地方**直接改顺**（不是只提意见）。这是最终合并进成品的版本。
  2. `upgrade/regression/<组号>.md`——**逐本回归判定**：恰好与组大小相同的行数，每行 `编号|通过` 或 `编号|修订：<一句话说明改了什么、为何不合理>`；无表头无总结。
- 回归定稿同样分 **5 段 × 3 本**落盘；回归报告可一次性写完（很短）。
- 导师产出依然必须满足第三节全部红线；**导师自己也不得在定稿里写剧透**。

## 六、合并方式（captain 用脚本做，agent 不碰）

- `scripts/validate_upgrade.py` 校验 drafts / approved 的结构、编号、剧名、角色名、零剧透、全中文，以及 regression 报告行数。
- `scripts/apply_upgrade.py` 把 `upgrade/approved/*.md` 的每块，包成 `### 讨论升级 / 高光辩论` 段，**幂等追加**到四卷终稿对应套的末尾（11 本高分本不加）。
- 随后 `scripts/build_box.py` 重新生成 100 本盒装本：主持人手册 / 本盒完整内容 / 说明书会带上「讨论升级」章节；角色卡、角色剧本、线索卡保持原有信息隔离。
- 最后重跑评审流水线（8 学生重新打分 → PM 新总榜 → 写进每本介绍），与本升级互不覆盖。

## 七、完成报告

写手 / 导师完成后各自 `send_message` 报告：产物路径、块数 / 行数、覆盖编号、自查结论（零剧透 / 全中文 / 角色名一致 / 分段纪律）。不建 todo、不派子 agent、不跑脚本、不做 git。
