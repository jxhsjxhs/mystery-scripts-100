# 百局 · 一百套可直接开本的原创剧本杀盒装本

> 100 套 2–4 人剧本杀**完整成品**：恐怖 / 反转 / 搞笑 / 职场厮杀，四卷各 25 套。
> 每本都是一套**可直接印、可直接发给玩家、可直接开本**的盒装物料——含封面图、每个角色的角色卡图（名字 / 身份 / 任务）、线索卡图、第一人称角色剧本、说明书、主持人手册、结局卡、盒面文案与本盒合订。

## 这套东西是什么

市面上多数「剧本设定集」只是给 DM 看的文档；本项目交付的是**成品盒装本**：

- **图画**：每本一张封面图、每个角色一张角色卡图（PNG，真实绘制）、一套线索卡图。
- **每个角色都有名字与任务**：角色卡印「角色名 / 身份 / 人前主张 / ◆你的任务」；**隐藏秘密刻意不印在卡上**，只在仅发给该玩家的第一人称《角色剧本》里——即信息隔离，玩家拿到的卡不会串供。
- **可直接宣读**：`盒面文案.md`（电商详情页 / 盒背 / 海报用，零剧透）+ `说明书.md` + `主持人手册.md`（含发本顺序、三幕、线索发放表、完整真相、复盘话术）。
- **可直接开局**：分角色《角色剧本》各 10 节（你是谁 / 公开背景 / 人前主张 / 只有你知道的秘密 / 你的任务 / 分幕行动指引 / 建议开场自我介绍…）。

四种口味：

| 卷 | 编号 | 套数 | 写手人设 | 基调 |
| --- | --- | --- | --- | --- |
| 恐怖本 | H01–H25 | 25 | 夜枭 | 民俗怪谈、都市传说、心理惊悚 |
| 反转本 | T01–T25 | 25 | 叙诡生 | 叙诡、身份互换、时间/文本陷阱 |
| 搞笑本 | C01–C25 | 25 | 哈哈镜 | 沙雕荒诞、社死、谐音与误会 |
| 职场厮杀本 | O01–O25 | 25 | 工位修罗 | 末位淘汰、抢功、背锅、期权与站队 |

每套 **2 / 3 / 4 人**之一，全中文，角色名全局唯一，编号连续；合计 **100 本 / 314 个角色 / 314 张角色卡图**。

## 怎么读 / 怎么用

- **想开本** → 进 `盒装本/<编号>_<剧名>/`：先读 `说明书.md` 和 `主持人手册.md`，把 `角色卡/*.png` 与 `角色剧本/*.md` 按人发下去，`线索卡.png` 搜证轮出示。
- **想通览成品** → [盒装本/盒装本总索引.md](盒装本/盒装本总索引.md)：100 本分卷表格、人数/时长/难度/题材、链到各盒目录。
- **想上架/印盒** → 每本的 `盒面文案.md`（零剧透宣传物料）与 `封面.png`。
- **想通览设定全貌** → [总览目录.md](总览目录.md) 与 [100套完整合集.md](100套完整合集.md)（四卷 100 套 9 字段设定全文合订）。

每套设定固定 9 字段结构（详见 [写作规范.md](写作规范.md)）：

```
## [H01] 《合婚帖》
- 题材 / 人数 / 时长 / 难度
### 背景            （100–200 字）
### 角色            （每人：身份。表面立场：…。隐藏秘密：…。个人目标：…。）
### 核心诡计  ### 关键线索（≥3 条可搜证物证）  ### 流程 / 分幕（三幕）
### 反转点 / 高潮  ### 真相与结局  ### 主持人提示（DM Notes）
```

质量红线：禁止模板化复制；反转必须能被前面的线索回看验证；线索必须可搜证；禁止用「做梦 / 失忆 / 外星人」一刀切收尾；每个角色都必须有隐藏秘密和个人目标。

## 它是怎么做出来的（三阶段流水线）

### 阶段一：100 套设定稿（4 写手 + 1 总审核）
1. **规范先行**：`写作规范.md` 写死 9 字段硬契约与质量红线，保证 100 套可机器校验。
2. **四位写手并行**：四卷各 25 套，每人带专属人设、母题清单与角色名前缀池，避免跨卷重名。
3. **合并校验**：`merge.py` → `validate.py draft` 校验 100 套、人数配额、角色名唯一、编号连续、字段/线索齐全。
4. **第 5 个全新 agent 总审核**：非四位写手中的任何一人，通读全 100 套，产出 `review/总审核意见书.md`（逐条改写超标背景、按母题去模板化题材、复核托底词、给分卷修改清单）。
5. **按意见修订、再生成剧本**：审核意见拆成两类补丁，由 `apply_patches.py` 一起套回初稿生成终稿（避免重发整卷丢内容）：`drafts/patches/<卷>.patch.md`（硬项，脚本从意见书自动抽取）+ `<卷>.soft.md`（四位写手投递的编号级软项）。
6. **终稿校验 + 合集**：`validate.py final` → `digest.py final` → `combine.py` 生成总览目录与完整合集。

### 阶段二：升级为可直接商业化盒装本（8 个 agent，4 组 ×〈写手 + 导师〉）
7. **确定性生成器 `build_box.py`**：物理物料（图片、信息隔离的角色剧本、卡面排版）**由脚本生成，不交给 agent 手敲**——保证 100 本零遗漏、314 张角色卡零缺、卡面不含隐藏秘密。
8. **8 个 agent 分 4 组做商业化文案**：每组 1 位「导师」（读终稿全文，产出逐本分析与**严禁剧透点**）+ 1 位「写手」（**只读零剧透素材表 + 导师指导**，产出可直接印的包装文案）。结构性防剧透：写手根本接触不到真相。
   - 导师 → `commercial/guidance/guide_<卷>.md`；写手 → `commercial/pack_<卷>.md`。
   - 契约见 [commercial/包装规范.md](commercial/包装规范.md)；素材表由 `gen_materials.py` 从终稿**刻意剔除秘密/反转/真相**后投影生成。
   - 若某卷写手因长文本偶发零输出，`gen_pack_fallback.py <卷>` 会按同一份导师指导与零剧透素材表确定性补齐该卷包装，保证 100 本不缺盒面文案。
9. **注入与批量生成**：`build_box.py` 读 `pack_<卷>.md`，把每本包装文案注入 `盒面文案.md` / `主持人手册.md` / `本盒完整内容.md`，批量产出 100 本目录与总索引。
10. **双重校验**：`validate_pack.py` 校验 4 卷包装与 4 份指导；`verify_box.py` 校验 100 本成品物料齐全、图片非空白、角色卡/剧本数==人数、信息隔离、包装全覆盖。

### 阶段三：低分本讨论升级 + 导师回归 + 重跑评审（本轮）

11. **首轮评审**：8 位人设互不相同的学生 agent 各自独立给 100 本打分（60–98，全中文、零剧透），1 位 PM agent 按 8 人均分降序排总榜、写总结并注入每本介绍。以该榜为准，**挑出均分低于 85 的 89 本**（11 本高分本原样保留）。
12. **6 个写手 agent 分组升级**：把 89 本按卷序切成 6 组（15/15/15/15/15/14），每组 1 位带人设写手，只读零剧透素材表，为每本补一段「讨论升级 / 高光辩论」（讨论焦点 / 分幕争点 / 两难抉择 / 高光引导 / 对抗钩子），专门把「讨论热不热闹」做上去——**零新增设定、零剧透、不改 9 字段**。
13. **6 个导师 agent 逐一合理性回归**：每组 1 位导师对照终稿核对角色名 / 线索 / 三幕，把「凭空新增 / 剧透 / 争点接不上物证 / 三幕对不上 / 语句不通」**直接改顺**，产出回归定稿 `approved/<组>.md` 与逐本判定 `regression/<组>.md`。
14. **合并回 100 本**：`apply_upgrade.py` 把通过的升级幂等追加为终稿末尾的 `### 讨论升级 / 高光辩论` 段（在 DM Notes 之后，不污染角色段/线索段）；`build_box.py` 重建 100 本时，升级只注入 `说明书.md` / `主持人手册.md` / `本盒完整内容.md`，**角色卡 / 角色剧本 / 线索卡 / 结局卡 / 盒面文案保持信息隔离**。
15. **重跑评审**：`gen_eval_materials.py` 把「讨论升级」概要并入评审素材（高分本无该行属正常），再派 **8 位全新学生 agent** 重新逐本打分、1 位 PM agent 全新撰写总榜与总结；`finalize_review.py` 把新名次 / 均分 / PM 荐语重新写进每本介绍、README 与总索引（幂等，覆盖上一轮名次）。
16. **收口校验**：`validate_upgrade.py`（升级稿 + 回归报告）、`validate.py final`（100 套 9 字段）、`verify_box.py`（成品物料 / 图片 / 隔离）、`verify_review.py`（总榜 / 名片 / 零剧透全中文）四重校验全部通过后提交。

> 全程中文、全程零剧透（学生与写手都接触不到真相）；物理物料与各轮数据一律由确定性脚本生成/合并，agent 只负责各自擅长的「文字」与「分析指导」。

## 脚本用法

> 制图脚本依赖 Pillow，请用带库的 python 运行 `build_box.py` / `verify_box.py`；其余纯文本脚本用 `python3` 即可。

```bash
# —— 阶段一：设定稿 ——
python3 scripts/validate.py draft        # 校验 4 卷初稿整卷
python3 scripts/merge.py                 # 合并分批初稿为整卷（幂等）
python3 scripts/digest.py draft          # 生成 review/ 初稿概览与诊断
python3 scripts/audit_extract.py         # 从意见书抽取硬项 → review/审核硬项.json
python3 scripts/gen_base_patches.py      # 由硬项生成 4 卷基础补丁
python3 scripts/apply_patches.py         # 合并基础+软项补丁 → 生成各卷终稿
python3 scripts/validate.py final        # 校验 4 卷终稿
python3 scripts/digest.py final          # 复核终稿背景字数与题材种类
python3 scripts/combine.py               # 生成总览目录.md 与 100套完整合集.md

# —— 阶段二：盒装本成品 ——
python3 scripts/gen_materials.py         # 终稿 → 4 卷零剧透素材表
# （8 个 agent 产出 guide_*.md 与 pack_*.md 后）
python3 scripts/gen_pack_fallback.py twist   # 可选：某卷写手零输出时，按导师指导确定性补齐该卷包装
python3 scripts/validate_pack.py all     # 校验包装文案与导师指导
python3 scripts/build_box.py             # 批量生成 100 本盒装本 + 总索引
python3 scripts/build_box.py H01         # 只生成 1 本样板
python3 scripts/verify_box.py            # 全量校验 100 本成品（图片/物料/隔离/注入）

# —— 阶段三：讨论升级 + 重跑评审 ——
python3 scripts/gen_upgrade_materials.py  # 89 本低分本 → 6 组零剧透升级素材
python3 scripts/validate_upgrade.py drafts   # 先校验 6 位写手升级稿
python3 scripts/validate_upgrade.py approved # 再校验 6 位导师回归定稿 + 判定
python3 scripts/apply_upgrade.py         # 幂等合并 89 本升级回四卷终稿（高分本原样）
python3 scripts/gen_eval_materials.py    # 把「讨论升级」概要并入 4 份评审素材
python3 scripts/reset_round2.py         # 归档首轮评分，清空 scores/ 防两轮混算
python3 scripts/aggregate_scores.py      # 8 学生 800 条 → 新 JSON / 总榜 / pm_input
python3 scripts/gen_pm_fallback.py       # 可选：PM 零输出时确定性兜底生成总结
python3 scripts/refresh_pm.py            # PM 总结数据幂等校对（应对名次大洗牌）
python3 scripts/finalize_review.py       # 新名次/均分/PM 荐语注入 100 本介绍 + README + 索引
python3 scripts/verify_review.py        # 总榜 / 名片 / 零剧透全中文严查
```

校验口径：每卷恰好 25 套（H/T/C/O 01–25 连续）；每套人数 2/3/4 且角色行数==人数；每卷 2 人≥6、3 人≥8、4 人≥6；9 字段齐全；关键线索 ≥3 条；角色名全局唯一；全中文。包装文案零剧透、全中文、25 块齐全、角色预告行数==人数。升级稿零新增/零剧透/角色名逐字一致/三幕恰好 3 行/对抗钩子角色名合规，导师回归 6 组判定齐全。成品 100 本物料齐全、图片非空白、信息隔离、包装全覆盖；评审名片 100 本齐全、名次/均分与权威 JSON 一致、零剧透且全中文。
