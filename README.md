# 百局 · 一百套原创剧本杀设定集

> 100 套 2–4 人剧本杀完整设定稿：恐怖 / 反转 / 搞笑 / 职场厮杀，四卷各 25 套。
> 由 4 位带人设的写手 agent 分卷创作，交第 5 位全新「总审核」agent 通审并给出修改意见后，再由写手按意见修订生成终稿。

## 这套东西是什么

一套可直接用于开脑洞、二次改编、或作为 DM（主持人）备稿的**剧本杀设定文档**，不是成品盒装本（不含印刷物料、卡牌图、音频）。每套剧本都是自洽的完整推理/欢乐闭环，包含：

- 背景、角色（每人含「表面立场 / 隐藏秘密 / 个人目标」）、核心诡计/机制
- ≥3 条可搜证的编号物证/证词线索、三幕流程、反转与高潮、真相与结局
- 主持人提示（DM Notes）

四种口味：

| 卷 | 目录 | 套数 | 写手人设 | 基调 |
| --- | --- | --- | --- | --- |
| 恐怖本 | `horror/` | H01–H25 | 夜枭 | 民俗怪谈、都市传说、心理惊悚 |
| 反转本 | `twist/` | T01–T25 | 叙诡生 | 叙诡、身份互换、时间/文本陷阱 |
| 搞笑本 | `comedy/` | C01–C25 | 哈哈镜 | 沙雕荒诞、社死、谐音与误会 |
| 职场厮杀本 | `office/` | O01–O25 | 工位修罗 | 末位淘汰、抢功、背锅、期权与站队 |

每套 **2 / 3 / 4 人**之一（不会更多，方便小局开局），全中文，角色名全局唯一，编号连续。

## 怎么读

- 想通览全貌 → [总览目录.md](总览目录.md)：分卷表格、每套人数/难度/时长/一句话卖点/角色。
- 想一次拿全文 → [100套完整合集.md](100套完整合集.md)：四卷 100 套合订。
- 想按卷读 → 各卷目录下的终稿文件（`恐怖本25套.md` / `反转本25套.md` / `搞笑本25套.md` / `职场厮杀本25套.md`）。

每套固定 9 字段结构（详见 [写作规范.md](写作规范.md)）：

```
## [H01] 《合婚帖》
- 题材：…
- 人数：2
- 时长：…
- 难度：…
### 背景            （100–200 字）
### 角色            （每人：身份。表面立场：…。隐藏秘密：…。个人目标：…。）
### 核心诡计
### 关键线索        （1. 2. 3. … 可搜证的物证/证词）
### 流程 / 分幕     （第一幕 / 第二幕 / 第三幕）
### 反转点 / 高潮
### 真相与结局
### 主持人提示（DM Notes）
```

质量红线：禁止模板化复制；反转必须能被前面的线索回看验证；线索必须可搜证；禁止用「做梦 / 失忆 / 外星人」一刀切收尾；每个角色都必须有隐藏秘密和个人目标。

## 它是怎么做出来的（流水线）

1. **规范先行**：先写死 `写作规范.md`（硬契约）和校验脚本，四位写手按同一模板产出，保证 100 套可机器校验。
2. **四位写手并行**：恐怖 / 反转 / 搞笑 / 职场厮杀各 25 套，每人带专属人设、专属母题清单与角色名前缀池，避免跨卷重名。
3. **初稿合并与机器校验**：`merge.py` 合并 → `validate.py draft` 校验 100 套、人数配额、角色名唯一、编号连续、字段/线索齐全；`digest.py` 产出概览与诊断。
4. **第 5 个全新 agent 总审核**：通读全 100 套，产出 `review/总审核意见书.md`——逐条改写超标背景、按母题细化题材标签、复核托底词、给分卷修改清单。**审核者不是四位写手中的任何一个。**
5. **按意见修订、再生成剧本**：审核意见拆成两类「改动字段补丁」，由 `apply_patches.py` 一起套回初稿、生成各卷终稿（避免重发整卷丢内容）：
   - `drafts/patches/<卷>.patch.md`：逐字照抄意见书 2.1/2.2 的**硬项**（23 段背景改写 + 75 个题材去模板化标签），由脚本从意见书自动抽取生成。
   - `drafts/patches/<卷>.soft.md`：四位写手按意见书第三节各自投递的**编号级软项**（英文残留中文化、辨识度补句、机制去剧透、角色改名、难度单值化、雷同机制改写等）。
6. **终稿全量校验 + 合集**：`validate.py final` → `digest.py final` 复核背景字数与题材种类 → `combine.py` 生成总览目录与完整合集。

```
juben100/
├── README.md                 本文件
├── 写作规范.md               统一硬契约（9 字段模板 + 质量红线）
├── 总览目录.md               100 套分卷表格与统计
├── 100套完整合集.md          100 套全文合订
├── horror/                   恐怖本终稿 25 套
├── twist/                    反转本终稿 25 套
├── comedy/                   搞笑本终稿 25 套
├── office/                   职场厮杀本终稿 25 套
├── drafts/                   初稿整卷与修订补丁（过程资产）
│   ├── patches/              修订补丁（基础硬项 + 四位写手的软项）
│   └── _discarded/           已作废/归档的中间稿（不入库）
├── review/                   审核输入、《总审核意见书》与终稿诊断
└── scripts/                  可复跑的校验与生成脚本
    ├── validate.py           初稿/终稿硬校验
    ├── merge.py              合并分批初稿为整卷
    ├── digest.py             生成概览与机器诊断（draft / final）
    ├── audit_extract.py      从意见书抽取硬项
    ├── gen_base_patches.py   生成 4 卷基础补丁
    ├── apply_patches.py      合并两类补丁 → 生成终稿
    └── combine.py            终稿 → 总览目录 + 完整合集
```

## 脚本用法

```bash
python3 scripts/validate.py draft     # 校验 4 卷初稿整卷
python3 scripts/validate.py final     # 校验 4 卷终稿（读各卷目录）
python3 scripts/merge.py              # 合并批次数稿为整卷（幂等）
python3 scripts/digest.py draft       # 生成 review/ 初稿概览与诊断
python3 scripts/digest.py final       # 复核终稿背景字数与题材种类
python3 scripts/audit_extract.py      # 从意见书抽取硬项 → review/审核硬项.json
python3 scripts/gen_base_patches.py   # 由审核硬项.json 生成 4 卷基础补丁
python3 scripts/apply_patches.py      # 合并基础+软项补丁，生成各卷终稿
python3 scripts/combine.py            # 生成总览目录.md 与 100套完整合集.md
```

校验口径：每卷恰好 25 套（H/T/C/O 01–25 连续）；每套人数 2/3/4 且角色行数等于人数；每卷 2 人≥6、3 人≥8、4 人≥6；9 字段齐全；关键线索 ≥3 条；角色名全局唯一；全中文。
